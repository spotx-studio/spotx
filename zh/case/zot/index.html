企業級員工福利系統數位化

主導產品設計 (Lead Product Designer) | 與 PM、前端及後端團隊密切協作

3 個月 Figma B2B 網頁系統

極速數位化工作流

將紙本審核流程從 2 週狂降至 3 天，且進度即時追蹤不漏接。

自動化規則引擎

系統化邏輯自動篩選資格，不符條件直接擋下，從根本杜絕人為錯漏。

一鍵匯出財務報表

自動生成轉帳檔與稅務申報資料，大幅降低跨部門對帳的痛苦。

專案挑戰

01

面臨的問題

解決方案

01
慢半拍且不透明的紙本流程（耗時 2 週）
流程全面數位化，將處理時間砍到剩 3 天，申請人也能隨時掌握最新進度，並直接在線上補件。

02
複雜資格審核容易產生人工錯漏
導入系統化規則引擎，自動幫員工把關申請資格，不會再誤申不符合條件的福利項目。

03
高風險的跨部門財務核對
確保紀錄自動化，財務可以直接從系統一鍵匯出標準的「轉帳檔」和「稅務所得檔」，保證數據 100% 精準。

目標與指標

UX 策略

梳理複雜的權限架構

系統牽涉多種角色權限與條件變化。我在前期先精準分類並釐清邏輯細節，確保各部門的操作體驗安全又合理。
設計系統

系統擴展與設計規範延伸

善用客戶既有的 Figma 設計規範進行優化與擴充，以支撐這次的高難度需求，同時維持跨系統的視覺統一。
開發協作

兼顧開發可行性的設計平衡

擔任 UI、前端與後端的橋樑，避免為了畫面酷炫而讓後端邏輯過度複雜，確保 API 結構乾淨好維護。

UX 規劃

第一階段：對齊需求與定義邏輯架構

打磨核心頁面的元素與細節

深入分析各類福利申請的必填欄位，重新組織資訊層級，讓原本繁雜的表單變得清晰易讀。

定義系統邏輯架構

我們梳理出了福利金的「共用額度邏輯」（例如：不同等親的喪葬撫卹金共享同一年度上限），從根本上簡化了後端的邏輯複雜度。

透過線稿建立溝通共識

發現客戶對抽象的 UX 概念比較難有畫面感，我提早引入低保真 (Low-fi) 線稿來輔助說明，大幅加速了雙方的討論與決策效率。

設計迭代

分享我如何微調設計，讓系統既好用又好開發

迭代 1：從「過度彈性」回歸「務實邏輯」

後端複雜度過高
我一開始想打造一個高度客製化、超彈性的模組。但後來發現公司的福利規定其實非常固定，過度的彈性只會搞死後端，卻沒帶來相對應的價值。
針對既有項目獨立設定
我們轉而針對現有的福利項目做獨立的條件設定。這樣不僅介面更直覺，系統運作也更穩固。
引進「共用額度」邏輯
延伸出更聰明的做法。例如「喪葬撫卹金」雖分為本人、一等親等不同項目，但我們設計了跨項目的額度檢查邏輯，完美解決了每年只能請領一次的業務需求。

迭代 2：打造行雲流水的審核體驗

畫面破碎與頻繁切換
原本設計了一個獨立的「完整審核專頁」，好處是一目了然，但在實際操作時，審核者必須頻繁在不同分頁之間來回切換、比對資料，非常不方便。
懸浮式情境操作區
我把獨立專頁砍掉，換成了「懸浮式的簡易簽核區塊」。現在委員只要上下滑動看完案件細節就能直接點擊簽核。雖然犧牲了一點排版的完整性，但操作便捷度直接點滿。

專案成果

我們達成了什麼？
建立穩固的溝通流程
透過提早引入低保真線稿，讓每次溝通都在重點上，成功幫助不熟悉 UX 流程的客戶把模糊的需求具體化。
設計系統的優化與延伸
不只是「套用」客戶原有的設計規範，而是針對這次的複雜需求進行了深度優化與擴充，確保多個內部系統間的視覺高度統一。
收斂出最務實的設計
捨棄了華而不實的炫技，把設計重心放在解決真實的業務邏輯，打造出貼近員工與 HR 實際工作習慣的務實系統。
完美平衡三方協作
在 UI 美感、前端切版與後端邏輯之間抓到了最佳的平衡點，讓整個開發團隊能高效完工，不留下惱人的技術債。

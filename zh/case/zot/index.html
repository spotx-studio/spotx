企業級員工福利系統數位化

主導產品設計 (Lead Product Designer) | 與 PM、前端及後端團隊密切協作

3 個月 Figma B2B SaaS

極速數位化工作流

將紙本審核流程從 2 週狂降至 3-5 天，且進度即時追蹤不漏接。

自動化規則引擎

系統化邏輯自動篩選資格，不符條件直接擋下，從根本杜絕人為錯漏。

一鍵匯出財務報表

自動生成轉帳檔與稅務申報資料，大幅降低跨部門對帳的痛苦。

跨部門、辦公室溝通

福利委員、申請人、財務、人資和高階主管皆會參與審核過程，溝通成本高昂且複雜，加上人員落在分散的辦公室，人為溝通失誤風險極高。

開發協作

兼顧開發成本的決策

擔任設計與工程橋樑，在 UX 彈性與後端 API 複雜度之間取得完美平衡，主動規避會產生龐大技術債的設計。

UX 戰略權衡

在「系統理想」與「商業現實」間的決策轉向

Sitemap 取捨：解決進入系統第一眼的混亂感

一開始我規劃了三套專屬的儀表板，想呈現豐富的數據監控。但客戶反應實際案件沒那麼多，且開發成本太高。
我識別到這會讓使用者進去系統「第一拍」就很亂，要花時間找東西，而非直接執行任務。雖然想做大，但在衡量開發成本與實用性後，我做了沒辦法的取捨，決定收斂為直覺的「申請列表」，讓使用者能以最短路徑完成任務。

降低消化成本：從抽象文檔轉向具體線稿

原本想先對齊嚴謹的欄位與邏輯，但客戶覺得純文字清單太抽象，消化成本極高。我發現這樣不僅溝通沒效率，還會埋下後期頻繁改動的技術債風險。
我隨即調整策略，改用低保真線稿搭配說明。雖然設計端變累了，但成功把冷冰冰的資訊架構轉化為具體共識，大幅加速了決策過程。

習慣權衡：以 Excel 匯入取代 Web 編輯

為了系統一致性，本來想推行網頁版名單編輯器，但 User 習慣用 Excel 處理大數據。如果強硬改變，會讓使用者對新系統產生強烈反感。
在「數位化美學」與「低學習成本」之間，我選擇了後者。改用上傳下載的模式雖然稍微沒那麼數位化，但卻是確保系統能被無縫採納、讓使用者不反感的明智決定。

架構與迭代決策

在工程開發成本與使用者體驗之間，尋找最優的戰略解法

福利金設定：捨棄萬用引擎以換取開發節奏

追求極致擴充的代價
一開始我想打造一個具備高度彈性的全自動規則引擎。但在與工程師對齊時，對方反映這種通用邏輯會讓 API 異常複雜，產生龐大的技術債，時程上根本趕不及。
務實的獨立頁面決策
我重新思考後發現政策變動頻率極低，其實不需要過度工程化。我決定轉向針對不同項目設計獨立設定頁，這雖然犧牲了萬用感，卻為團隊省下數週開發時間，是投資報酬率最高的決定。

簽核體驗：解決頻繁切換分頁的斷裂感

獨立簽核頁的比對困境
原本我設計了一個很美觀的完整簽核頁面。但進入操作測試後，委員反映他們必須在附件與申請資料之間不停切換分頁，資訊非常破碎，造成嚴重的認知超載。
犧牲排版美感換取操作效率
我最後推翻全屏設計，改採隨畫面滑動的懸浮簽核盤。雖然犧牲了視覺完整性，但解決了委員需要同屏比對數據的剛性需求，讓高壓審核時的操作效率直接點滿。

狀態管理：以撤回機制消除數據衝突

競態條件引起的數據風險
我識別出如果在審核流程中讓使用者隨時編輯，財務端會讀取到變動中的髒數據，引發致命的數據衝突。在使用者自由度與財務數據安全之間，我必須做出選擇。
導入強制撤回護欄
我重新定義了狀態機並導入撤回機制。雖然多了一個步驟，但確保了每一筆進入審核的資料都是不可變動的，從底層守護了企業財務誠信，這是一次站在安全性立場的必要取捨。

附件管理：減少審核者的視覺與判斷壓力

檔名混亂導致的認知超載
原本附件上傳很自由，但委員反饋員工傳的檔名都很隨性（如照片.jpg），讓他們得逐一打開確認類別，這在業務高峰期極易產生人為判斷失誤。
防禦性設計：語意化類別
我決定增加申請端的一點點操作負擔，強制要求挑選類別。這項微小的權衡顯著降低了審核者的心理負荷與人為失誤，這是在 B2B 系統中保護管理者的必要手段。

系統治理：在頻繁變動中維持單一事實來源

建立版本控制日誌
專案進行三個月改了 30 多次，且客戶消化純文字的能力有限。我主動建立了版本日誌，紀錄每一次的決策與欄位變動，確保設計與開發在無數次轉向後依然能精準同步。

專案成果

從混亂營運到精準治理的量化結果
-50%
人為錯誤接觸點裁撤
原本超過10項條件需要人工手動比對，我透過導入規則引擎自動校驗，精確減少了8個最容易產生失誤的人為接觸點。這項改進讓財務人員從高壓的重複驗證中解脫，將人為誤損風險降至最低。
+40%
研發時程精準節省
透過權衡捨棄過度複雜的規則引擎，改採務實的模組化頁面設定，為工程團隊節省了將近 40% 的開發時程，平衡設計美感、系統彈性與開發成本。
-75%
審核週期大幅縮短
成功將原本14天的積壓流程壓縮至5天。透過重新定義狀態機與撤回機制，我徹底消弭了過去實體紙本遞送造成的資訊真空期，讓整體營運效率提升了 78%。
0%
跨部門數據對帳衝突
建立單一事實來源，解決了福利委員、財務與人資之間長期數據不一致的問題。透過撤回機制的底層鎖定，實現跨辦公室、跨單位的數據零衝突，讓對帳不再需要人工反覆校對。

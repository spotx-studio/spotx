企業級員工福利系統數位化

主導產品設計 (Lead Product Designer) | 與 PM、前端及後端團隊密切協作

3 個月 Figma B2B SaaS

災難與痛點

原本企業內部的福利金申請高度依賴紙本作業。不僅財務部門耗費大量時間溝通與收集資料，委員在人工審核的過程中也極易產生人為錯漏。

核心策略

透過系統化的 UI/UX 重構將線下流程轉移至線上，並建立一套具備嚴謹「狀態管理 (State Management)」且「高度對齊 React 前端開發」的企業級系統架構。

極速數位化工作流

將紙本審核流程從 2 週狂降至 3 天，且進度即時追蹤不漏接。

自動化規則引擎

系統化邏輯自動篩選資格，不符條件直接擋下，從根本杜絕人為錯漏。

一鍵匯出財務報表

自動生成轉帳檔與稅務申報資料，大幅降低跨部門對帳的痛苦。

專案挑戰

01

面臨的問題

解決方案

01
慢半拍且不透明的紙本流程（耗時 2 週）
流程全面數位化，將處理時間砍到剩 3 天，申請人也能隨時掌握最新進度，並直接在線上補件。

02
複雜資格審核容易產生人工錯漏
導入系統化規則引擎，自動幫員工把關申請資格，不會再誤申不符合條件的福利項目。

03
高風險的跨部門財務核對
確保紀錄自動化，財務可以直接從系統一鍵匯出標準的「轉帳檔」和「稅務所得檔」，保證數據 100% 精準。

目標與指標

UX 策略

收斂核心邊界

系統牽涉多種角色與複雜條件。我透過任務分析圖精準收斂功能模組，避免後續無效的開發浪費與方向偏移。
DesignOps

系統擴展與交付規範

導入 Semantic Tokens 邏輯，善用客戶既有的 Figma 規範進行深度擴充，打造高度對齊 React 的元件庫。
開發協作

兼顧開發成本的決策

擔任設計與工程橋樑，在 UX 彈性與後端 API 複雜度之間取得完美平衡，主動規避會產生龐大技術債的設計。

UX 規劃

梳理混沌：從抽象清單到具體系統邏輯

釐清邊界：用「使用者任務」收斂核心模組

客戶初期僅提供了一份基於想像的功能清單。我沒有直接畫 Wireframe，而是先繪製了「使用者任務分析圖」。透過視覺化地圖，引導利害關係人釐清必要與不必要功能（如捨棄系統內建即時通訊），成功收斂出核心模組。

解決極端情境：化解「狀態機」與權限衝突

當案件已進入審核，申請人若需要「編輯修改」，會引發嚴重的狀態機 (State Machine) 衝突。我導入了「撤回 (Withdraw) 機制」，統一了雙方眼中的狀態，並讓系統能精準串接通知邏輯，徹底解決 Edge Cases 模糊地帶。

混合式 UX 提案：透過線稿建立溝通共識

發現客戶對抽象的純 UX 流程圖較難有畫面感，我提早引入低保真 (Low-fi) 線稿輔助說明。這種「混合式 UX 規劃」大幅加速了雙方的討論與決策效率，為後續合作奠定了極佳的信任基礎。

架構與迭代決策

在 UX 彈性與工程成本間取得完美平衡

迭代 1：從「過度彈性的通用驗證」回歸「務實獨立頁面」

後端複雜度過高
原本考量未來擴充性，我構思了一套強大的「通用邏輯驗證系統」讓委員自由組合條件。但在與技術團隊討論後，發現過度的彈性會對後端造成極龐大的開發成本。
針對既有項目獨立設定
評估後發現福利金政策變動頻率極低，我們轉而針對不同項目設計「獨立條件設定頁面」。介面更直覺，系統運作也更穩固。
創造巨大商業價值
這個架構決策以極低的 UX 妥協，換取了省下數週後端開發時間的巨大商業價值，展現了身為 Design Technologist 對開發成本的精準評估。

迭代 2：打造行雲流水的審核體驗

畫面破碎與頻繁切換
原本設計了一個獨立的「完整審核專頁」，好處是一目了然，但在實際操作時，審核者必須頻繁在不同分頁之間來回切換、比對資料，非常不方便。
懸浮式情境操作區
我把獨立專頁砍掉，換成了「懸浮式的簡易簽核區塊」。現在委員只要上下滑動看完案件細節就能直接點擊簽核。雖然犧牲了一點排版的完整性，但操作便捷度直接點滿。

DesignOps 落地：零摩擦的工程交付

1:1 對接 React 開發邏輯，全面導入 Semantic Tokens 打造高擴充性系統。
上傳彈跳視窗 數據表格 網格系統 選單元件

專案成果

我們達成了什麼？
零摩擦的工程交付
建立帶有前端邏輯的交付標準，專案交付後，工程師「幾乎沒有來找我額外要過任何東西或釐清規格」，實現真正的高效開發。
節省巨大的後端成本
主動放棄華而不實的「通用驗證引擎」，改為務實的獨立模組，以極小的 UX 妥協為開發團隊省下數週的開發期。
建立穩固的協作溝通
透過「混合式 UX 規劃」提早引入線稿，成功幫助不熟悉 UX 流程的客戶把模糊需求具體化，建立極佳信任基礎。
精準的狀態機管理
導入「撤回」機制，精準化解線上審核與編輯權限的邊緣情境 (Edge cases) 衝突，維持系統邏輯的嚴謹性。

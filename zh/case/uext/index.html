醫療級儀表板：讓病患監控與即時救援更流暢

主導 UI/UX 設計 | 與跨部門團隊（PM、後端工程師、業務）緊密協作

3 個月 Figma HTML CSS JS

即時儀表板與離床警報

簡化日常巡視流程，大幅提升對突發狀況的反應速度。

客製化警報參數設定

針對不同病患的安全需求彈性調整，有效降低誤報率。

動態操作視窗

在不干擾主監控畫面的情況下，快速檢視或修改病患細節。

面臨的問題

解決方案

目標與指標

UX 策略

收斂流程並定義核心功能

將各方利害關係人（工程、業務、醫療人員）的需求整合，在「技術可行性」與「臨床同理心」之間取得完美平衡。
響應式設計

任務導向的 UI 架構

針對護理人員在不同場景（護理站大螢幕 vs 走廊巡房手機）的任務需求，量身打造最合適的響應式佈局。
前端切版

高相容性的前端開發交付

親自寫出乾淨、跨瀏覽器相容的 HTML/CSS/JS 程式碼，確保後端團隊能無痛串接資料庫。

UX 規劃

第一階段：任務分析、使用者流程、網站地圖

定義核心任務與使用者流程

完整描繪護理人員的日常旅程，預判各種臨床的突發狀況，讓開發團隊與客戶在專案初期就建立清晰的共識。

大膽收斂：專注於「警報管理」

經過幾次訪談迭代，我們發現護理人員更傾向用醫院原有的系統寫病歷紀錄。因此我們果斷砍掉多餘的紀錄功能，全力專注在「即時警報」，這不僅讓介面更乾淨，也省下了大量不必要的開發時間。

設計風格

視覺識別：風格定調與 UI 元素

首頁設計迭代

分享我如何微調設計，讓它更貼近醫療人員的極限使用情境

版本 1 - 初版草圖

畫面太長，需要一直滾動
護理人員在忙碌時需要「一眼看清」所有病床狀態。關鍵數據必須在不碰滑鼠的情況下就能直接看到。

版本 2 - 實驗與強化

強化狀態卡片設計
  • 加入狀態專屬的背景色塊，一眼就能辨識異常。
  • 大幅放大病床號碼，提升遠距離閱讀性。
資訊密度過高
卡片塞了太多東西，反而讓人眼花撩亂，降低了掃視的效率。

版本 3 - 減法與優化

可收合的通知面板
  • 展開模式：適合護理站進行詳細的管理工作。
  • 收合模式：釋放螢幕空間，適合日常巡房快速查看狀態。
資訊斷捨離
勇敢拿掉非緊急的健康數據，把珍貴的版面留給最關鍵的「警報通知」與「病患辨識」。
搜尋列的巧妙移位
把搜尋列移到該區塊標題的下方，清楚劃分這是「搜尋病患」的區域搜尋，而非全站搜尋，操作邏輯更清晰。

系統化開發交付流程

1:1 對接開發邏輯，打造高擴充性的設計系統
按鈕元件 輸入框 進階單選框 搜尋列

專案成果

我們達成了什麼？
協助超過 1,000 名醫護人員
系統成功上線部署，大幅簡化了上千位護理人員的日常監控流程與緊急反應時間。
零修改的高效交付
在線稿階段就先把技術限制溝通清楚，徹底消除了後續設計反覆修改的噩夢，讓開發週期直接縮短 30%。
可擴展的 DOM 架構
捨棄把每個彈跳視窗寫死的笨方法，我改用 JavaScript 動態注入，讓 HTML 結構保持輕巧，後端工程師串接資料也更輕鬆。
搭起設計與程式的橋樑
發揮 Design Technologist 的優勢，第一時間抓出前端開發的可行性問題，確保最終網頁 100% 還原 Figma 的設計，且不留任何技術債。

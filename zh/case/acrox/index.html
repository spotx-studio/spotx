的認知負擔與學習門檻

客戶希望能打入大眾市場，但傳統電競軟體充斥著工程思維，將進階功能與基礎設定混為一談。這種陡峭的學習曲線與雜亂的資訊層級，會讓新手玩家在第一拍就放棄使用。

目標與指標

體驗戰略

主動發起產品健檢

打破單純「美化介面」的侷限，透過深度的體驗診斷，主動補齊缺失的功能邏輯，重新定義玩家的完整客製化旅程。
架構重構

解開軟硬體邏輯死結

開發混合式覆蓋架構，在各種複雜的電競硬體設備上，完美平衡「全域同步（批次修改）」和「個別客製化」的優先級衝突。
防呆結構

消除導覽迷航感

在有限的筆電螢幕空間中，優化介面佈局與視覺資訊層級，讓使用者不需要去猜測設定藏在哪裡，降低新手的學習門檻。

UX 戰略決策

在「客戶商業期望」與「真實玩家體驗」間的權衡

產品健檢：從視覺美化轉向邏輯補完

一開始客戶只希望我針對現有的 Wireframe 進行 UI 介面的視覺美化，讓畫面看起來更專業。但我實際盤點後，發現原稿漏掉了大量關鍵情境，如本地設定檔的權限、截圖路徑等。
我識別到如果只做表面美化，玩家在實際操作時會處處碰壁，最終導致產品失敗。雖然這超出了原本的發包範圍，但我還是說服客戶先暫停視覺，進行深度的 UX 診斷，並主動提出了 10+ 項核心功能的優化與擴充，確保產品邏輯完整可行。

混合式架構：解開「全域 vs. 單機」的權限死結

針對燈效同步，原本的構想是把所有設定塞在一起。但工程測試與玩家回饋指出，這會讓人分不清現在改的是「全部設備」還是「單一滑鼠」，底層邏輯嚴重打架。
我發現如果沒有明確的層級，玩家辛苦調好的單一燈效很容易被莫名其妙洗掉，產生極大挫折感。為了徹底解決這個死結，我提出「混合式架構」，將全域同步抽離成獨立的覆蓋層 (Override)。打開同步時覆蓋單機設定，關閉則恢復。雖然這增加了開發複雜度，但確保了軟硬體整合 100% 不打架。

巨集邏輯的妥協與收斂

巨集本質上是一連串指令，與單一硬體無關，所以我最初強烈建議將它拉出來，做成一個獨立的全局管理頁面。但客戶基於他們的市場考量，堅持要將巨集歸屬在個別裝置的頁籤之下。
我意識到如果直接照做，玩家會陷入「在滑鼠頁面裡設定鍵盤按鍵」的邏輯錯亂。在無法改變商業決策的情況下，我做了沒辦法的取捨（除了不合邏輯的耳機與喇叭外），將巨集的 UI 模組完全標準化，透過跨裝置一致的排版設計，來彌補並降低這種「反直覺架構」帶來的學習成本。

設計風格

視覺識別：風格定調與介面元素

設計迭代與微調

從大架構的佈局，到細節元件的資訊層級，展現極致推敲。

迭代 1：結構上的防迷航優化 (三階段佈局演進)

零碎的佈局嘗試與視覺跳動
為了在筆電狹小的螢幕內塞入龐大設定，我一開始將基礎設定放左側，後來配合客戶喜好改放到裝置預覽圖的右下方。但因為每個裝置設定項目多寡不同，導致排版會隨著切換忽高忽低。
統一「三欄式」佈局的決定
我識別到這種「東一塊西一塊」的排版會讓使用者每次都要重新尋找功能，體驗極度破碎。我決定犧牲一點裝置預覽圖的空間，統一改為「三欄式佈局」，將基礎設定固定在右手邊。這讓使用者不需要埋頭苦幹去猜設定藏在哪，徹底消弭了切換設備時的視覺迷航。

迭代 2：設定檔詳情頁的資訊重心翻轉

滿版封面導致的瀏覽限制
在設定檔的詳細頁面，原本為了視覺美感，我設計了一個滿版的精美封面大圖放在最上方。但內部 Review 時發現，這樣會導致最重要的「設定細節」被往下擠，需要大量無效滑動。
30/70 分區提升閱讀效率
我意識到這完全放錯了重點，對專業玩家來說，快速比對參數遠比欣賞圖片重要。雖然滿版圖很美，但我果斷推翻原設計改採「左右 30/70 分區」。左側保留基本資料，右側一次性展開所有參數，讓資訊密度回歸專業工具的本質。

迭代 3：設定檔卡片的瀏覽效率提升

優化視覺層級與資訊密度
在列表呈現上，我將「設備型號」標籤層級往前拉，並加入「遊戲圖示」讓玩家能憑直覺秒速辨識。同時刻意縮減了封面圖片的高度，確保在一次畫面滾動中能容納更多的卡片，極大地提升了尋找與瀏覽的效率。
